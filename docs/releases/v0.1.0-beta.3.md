# v0.1.0-beta.3 – Beta release

## Deutsch

Beta.3 behebt den auf VM 104 nachgewiesenen Setup-Fehler. Die Variable
`CONFIG_SCHEMA` wurde im Modul als Service-Schema verwendet, wird von Home
Assistant aber als YAML-Konfigurationsschema interpretiert. Dadurch wurde die
Integration mit „Invalid config“ nicht geladen. Das Service-Schema heißt jetzt
`SEND_SCHEMA`.

Die veraltete dynamische Beschreibung mit `{device_count}` wurde vollständig
entfernt. TTS-Engines werden aus den vorhandenen `tts`-States erkannt, sodass
Piper nicht mehr von der Entity-Registry abhängt. Die Tests verwenden jetzt
die echte HA-Integrationserkennung sowie echte Config- und Options-Flow-
Aufrufe.

Die Live-Installation wurde nicht verändert, nicht neugestartet und nicht
reloadet. Nach dem HACS-Update ist ein Home-Assistant-Neustart erforderlich,
damit der neue Python-Code geladen wird. Browser-/Frontend-Caches können
anschließend mit einem vollständigen Browser-Reload geleert werden.

## English

Beta.3 fixes the setup failure proven on VM 104. The module used the name
`CONFIG_SCHEMA` for a service schema, but Home Assistant interprets that name
as the integration's YAML configuration schema. The integration therefore
failed with “Invalid config”. The service schema is now named `SEND_SCHEMA`.

The obsolete dynamic description containing `{device_count}` was removed
completely. TTS engines are discovered from actual `tts` states, so Piper no
longer depends on the entity registry. Tests now use real HA integration
discovery and real Config Flow and Options Flow calls.

The live installation was not changed, restarted or reloaded. A Home Assistant
restart is required after the HACS update so the new Python code is loaded.
Browser/frontend caches can then be cleared with a full browser reload.
